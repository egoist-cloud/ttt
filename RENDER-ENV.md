# Что сделать в Render, чтобы всё заработало

Проверено против твоего текущего списка Environment Variables.

---

## 1. Переменные, которые уже есть — ничего не трогай

Код их читает, они работают:

| Переменная | За что отвечает |
|---|---|
| `DISCORD_TOKEN` | токен бота (**перевыпусти**, старый светился) |
| `GUILD_ID` | ID сервера |
| `LOG_CHANNEL_ID` | логи автосинхронизации |
| `DB_CHANNEL_ID` | профили игроков |
| `ERROR_LOG_CHANNEL_ID` | ошибки бота |
| `ALLOWED_ROLE_ID` | кто может рассматривать заявки |
| `SPAM_VOTE_ROLE_ID` | право повторного голоса (дыра «один человек = 2 голоса» закрыта в коде) |
| `AUTO_ROLE_ID` | роль при принятии заявки |
| `ACTIVITY_ROLE_ID` | роль для `/activity_all` |
| `BYPASS_ROLE_ID` | обход запрета на заявки (**раньше был мёртвым, теперь работает**) |
| `CLAN_NAME`, `CLAN_URL` | название клана и ссылка |
| `STEAM_API_KEY` | Steam API + проверка владения при `/link` |
| `CS2RED_*` (16 шт.) | cookie админки cs2red |
| **`AI_REPORT_CHANNEL_ID`** | **работает как канал логов ИИ** — код читает и `AI_LOG_CHANNEL_ID`, и твой вариант |

## 2. Добавить обязательно

| Переменная | Значение | Зачем |
|---|---|---|
| `DATA_DIR` | `/data` | иначе данные живут в контейнере и стираются при каждом деплое |
| **`DEPUTY_ROLE_ID`** | ID ролей через запятую, например `111111111111111111,222222222222222222` | **заместитель закрывает заявку ОДНИМ нажатием**, без второго голоса. Ролей может быть несколько |

И **одно из двух** для ИИ:

| Вариант | Что задать | Комментарий |
|---|---|---|
| Gemini (рекомендую) | `GEMINI_API_KEY=<ключ>` | ключ бесплатно: https://aistudio.google.com/apikey — формат API сверен с официальной спецификацией |
| LLM7 (у тебя уже есть ключ) | ничего не добавлять | код сам подхватит `LLM7_API_KEY` как резервный провайдер |

Про LLM7 честно: этот API я из своей песочницы проверить не смог.
Код обращается к `https://api.llm7.io/v1/chat/completions` с моделью
`gpt-4o-mini` (меняется через `AI_BASE_URL` и `AI_MODEL`). Если провайдер
ответит ошибкой — в канале логов ИИ будет видно HTTP-код и текст ответа,
поправим одной переменной. Gemini-путь проверен по спецификации.

## 3. Добавить по желанию

| Переменная | Значение | Зачем |
|---|---|---|
| `GITHUB_TOKEN` | PAT с правом Contents: Read and write | хранение привязок в GitHub (см. раздел 5) |
| `GITHUB_REPO` | `логин/репозиторий-для-данных` | **отдельный** репозиторий, не тот, из которого деплоится бот |
| `GITHUB_BRANCH` | `main` | ветка для данных |
| `NO_COOLDOWN_ROLE_ID` | ID роли | её владельцам не действует кулдаун `/link` |
| `ROLE_IDS_JSON` | `{"VIP": 123, "Moderator": 456}` | искать роли по ID, а не по имени — надёжнее |
| `ROLE_MAP_JSON` | `{"7": "Спонсор", "13": "Гл.Модер"}` | связать roleId 7 и 13 с ролями Discord |
| `REVIEWER_ROLE_ID_2`, `EXTRA_REVIEWER_ROLE_1..3` | ID ролей | дополнительные роли ревьюеров |
| `APPLICATIONS_CHANNEL_ID`, `THREADS_CHANNEL_ID`, `APPLICATION_LOGS_CHANNEL_ID` | ID каналов | сейчас зашиты в код, можно вынести |
| `APPS_LOG_CHANNEL_ID` | `1511463623703265361` | канал карточек решений (это значение уже стоит по умолчанию) |
| `UNLINKED_CHANNEL_ID` | `1555204495682568202` | канал отчёта «кто не привязан через /link» (по умолчанию уже он) |
| `VOTES_REQUIRED` | `2` | сколько разных голосов нужно (по умолчанию 2) |
| `LINK_VERIFY` | `1` | подтверждение владения Steam при `/link` (по умолчанию включено) |
| `LINK_COOLDOWN_SECONDS` | `30` | пауза между `/link` |
| `SYNC_INTERVAL_MINUTES` | `15` | период автосинхронизации ролей |
| `AI_MODEL` | пусто / `gemini-3.8-flash` | модель ИИ |
| `AI_THINKING_LEVEL` | пусто / `low` / `medium` | «размышления» Gemini (дороже и медленнее) |
| `AI_ERROR_INTERVAL_MINUTES` | `15` | как часто ИИ разбирает ошибки |
| `AI_ASK_COOLDOWN_SECONDS` | `20` | антифлуд на `/rules`, `/ask` |
| `RULES_API_URL` | URL JSON правил | если найдёшь настоящий эндпоинт правил |

## 4. Переменные, которых в коде нет

Можно удалить — вреда не будет, но и пользы тоже:

| Переменная | Почему не нужна |
|---|---|
| `BANNED_ROLE_ID` | баны берутся из cs2red API, роли бота не используются |
| `MUTED_ROLE_ID` | то же самое для мутов |
| `COOLDOWN_HOURS` | срок запрета модератор вводит в модальном окне |

`LLM7_API_KEY` — **не удаляй**: он теперь используется как резервный провайдер ИИ.

## 5. Настройки самого сервиса (не Environment)

| Настройка | Значение |
|---|---|
| Build Command | `pip install -r requirements.txt` |
| Start Command | `python script.py` |
| Health Check Path | `/` |
| Auto-Deploy | включён — значит обычный `git push` обновляет бота |
| Disk (обязательно для сохранности данных) | Mount Path: `/data` |
| `PORT` | задавать **не нужно**, Render подставит сам |

## 6. Про хранение данных — выбрать одно

**Вариант А (правильный): Persistent Disk.**
Render → сервис → Disks → Add Disk → Mount Path `/data`, затем `DATA_DIR=/data`.
Данные переживают деплой и рестарт. На бесплатном тарифе диск не даётся.

**Вариант Б: репозиторий GitHub под данные** (`GITHUB_TOKEN` + `GITHUB_REPO`).
Как работает:
* при старте бот подтягивает из репозитория файлы, которых нет локально;
* после изменений (например, `/admlink`) выгружает изменившиеся файлы;
* повторно один и тот же файл не отправляется — сравниваются хеши;
* в сообщение коммита добавляется `[skip render]`, чтобы Render не
  перезапускал бота на каждый коммит с данными.

⚠️ **Заведи для данных ОТДЕЛЬНЫЙ репозиторий** (например `quantum-data`) и не
подключай его к Render. Если писать данные в тот же репозиторий, из которого
идёт деплой, каждый коммит будет новым деплоем.
⚠️ Репозиторий с `links.json` содержит Discord ID и SteamID живых людей.
Либо делай его **приватным**, либо используй диск.

`players_db.json` в синхронизацию по умолчанию **не входит**: он большой и
содержит персональные данные, а восстановить его можно командой `/player_info`.

## 7. Порядок действий целиком

1. Залить в GitHub: `script.py`, `ai_rules.py`, `github_sync.py`,
   `requirements.txt`, `.env.example`, `.gitignore`, `DEPLOY-RENDER.md`,
   `RENDER-ENV.md`. Удалить старый `dist/quantum-bot-panel.zip`.
2. Render задеплоит автоматически (Auto-Deploy).
3. Environment → добавить `DATA_DIR=/data` и ключ ИИ.
4. Disks → Add Disk → Mount Path `/data`.
5. Environment → `GITHUB_*`, если идёшь вариантом Б.
6. Открыть логи Render. Должно быть:
   ```
   🤖 ИИ: включён, модель gemini-3.8-flash, запросов 0, ошибок 0 — работает
   📚 Правила: ...
   ☁️ GitHub-хранилище: ...
   ✅ Глобальная проверка доступа подключена
   ✅ ClanView добавлен (заявки живут после рестарта)
   ✅ Все фоновые задачи запущены
   ✅ Бот ... готов!
   ✅ Команд синхронизировано: 24
   ```
7. В Discord проверить: `/ping`, `/health`, `/rules 2.2`.
8. Один раз написать `!setup` в канале заявок — больше не потребуется.
9. Положить `rules.txt` в `/data` (шаблон — `rules.example.txt`) и вызвать `!ai_scan`.

## 8. Частые проблемы

| Симптом | Причина и решение |
|---|---|
| Бот не поднимается, в логах `❌ DISCORD_TOKEN не задан` | не задана переменная окружения |
| `Не найден модуль discord` | не выполнен Build Command |
| Данные обнулились после деплоя | нет диска и нет `GITHUB_*` |
| `⚠️ ai_rules.py не загружен` | файл не залит рядом со `script.py` |
| `⚠️ github_sync.py не загружен` | файл не залит рядом со `script.py` |
| `/ping` пишет «выключен» | нет ни `GEMINI_API_KEY`, ни `LLM7_API_KEY` |
| Бот засыпает через ~15 минут | бесплатный тариф Web Service: нужен пингер или платный инстанс |
| Роли не выдаются | у бота нет права Manage Roles либо имя/ID роли не совпало (`/health` покажет) |
| `!setup` снова нужен | быть не должно: если повторилось — напиши, посмотрим логи |
