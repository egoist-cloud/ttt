# Деплой на Render через GitHub

## 0. Что важно понять до начала

Данные бота (`links.json`, `players_db.json`, `votes.json`, `seen.json`) лежат
**файлами рядом со скриптом**. У Render файловая система контейнера
**временная**: при каждом деплое, рестарте и перезапуске инстанса файлы
возвращаются к состоянию из репозитория. Всё, что бот записал за время работы
(новые привязки, голосования, активность), будет потеряно.

Поэтому нужен **Persistent Disk**:

1. Render → сервис → **Disks** → Add Disk.
2. Mount path: `/data`
3. Environment → `DATA_DIR=/data`

После этого данные живут между деплоями. Диск на бесплатном тарифе не даётся —
это платная опция.

## 1. Репозиторий

```bash
git init
git add .
git commit -m "quantum bot"
git branch -M main
git remote add origin <ссылка на репозиторий>
git push -u origin main
```

`.env` в репозиторий не попадает — он в `.gitignore`. Шаблон: `.env.example`.

## 2. Сервис на Render

- **New** → **Web Service** (нужен из-за health-сервера Flask внутри `script.py`).
- Build Command: `pip install -r requirements.txt`
- Start Command: `python script.py`
- Health Check Path: `/`

`script.py` сам поднимает Flask на `$PORT` и отвечает `Bot is running` — именно
это и проверяет Render.

Альтернатива — **Background Worker** (порт не нужен), но он платный.

## 3. Переменные окружения

Задаются в Render → Environment. Обязательный минимум:

| Переменная | Значение |
|---|---|
| `DISCORD_TOKEN` | **новый** токен из Developer Portal (старый светился в переписке) |
| `GUILD_ID` | ID сервера |
| `ALLOWED_ROLE_ID` | роль модераторов заявок |
| `SPAM_VOTE_ROLE_ID` | **не равна** `ALLOWED_ROLE_ID` |
| `DEPUTY_ROLE_ID` | роль заместителей: закрывают заявку одним нажатием |
| `AUTO_ROLE_ID` | роль, выдаваемая при принятии заявки |
| `STEAM_API_KEY` | ключ Steam Web API |
| `CS2RED_TOKEN`, `CS2RED_BH`, `CS2RED_YASC`, `CS2RED_BROWSER_ID`, `CS2RED_YANDEXUID` | cookie админки cs2red |
| `DATA_DIR` | `/data` (если подключён диск) |

Полный список с комментариями — в `.env.example`.

⚠️ `DISCORD_TOKEN` и cookie cs2red — это полный доступ к боту и к админке
сайта. Не вставляй их в чаты и в Issues.

## 4. Простой на бесплатном тарифе — главная засада

Бесплатные Web Service у Render засыпают после ~15 минут **без входящих
HTTP-запросов**. Подключение к Discord Gateway по websocket это условие не
выполняет, поэтому «сам по себе» бот засыпает даже когда работает.

Варианты:

1. Платный инстанс (не засыпает).
2. Внешний пингер каждые 5–10 минут: UptimeRobot, cron-job.org и подобные,
   URL — `https://<сервис>.onrender.com/`. Это известный обходной путь, но
   полагаться на него для 24/7 не стоит: Render периодически перезапускает
   бесплатные инстансы, и бот будет недоступен несколько минут.

Проверь актуальные условия своего тарифа в панели Render — правила меняются.

## 5. Только один экземпляр

Нельзя держать бота одновременно на Render и на домашнем ПК. Два подключения
одним токеном → Discord отключает одно, плюс обе копии могут писать в базу и
выдавать роли. Перед запуском на Render останови локального бота.

## 6. Проверка после первого деплоя

В логах Render должно появиться:

```
✅ Бот <имя> готов!
✅ Команд синхронизировано: 24
✅ ApplicationManagement view добавлен
✅ Глобальная проверка доступа подключена
✅ Все 2 фоновых задачи запущены
```

Затем в Discord:

- `/ping` — бот жив, показывает аптайм и число cookie;
- `/health` — полная диагностика: права бота, доступность cs2red и Steam,
  состояние JSON-файлов, задачи, каналы, дубли SteamID (команда доступна
  только модераторам — это и есть проверка, что доступ работает);
- `/link` — проверка привязки с подтверждением владения Steam.

## 7. Обновление кода

1. Правишь код локально.
2. `git push` → Render собирает и деплоит автоматически.
3. С подключённым диском данные на `/data` переживают деплой.

Перед крупными правками скачай копию файлов с диска (Render → Shell:
`cp /data/*.json /tmp/ && ...`) или просто выгрузи их через `/export_members`.

## 8. Если что-то не так

| Симптом | Причина |
|---|---|
| `❌ DISCORD_TOKEN не задан!` и код возврата 1 | не задана переменная окружения |
| `Не найден модуль discord` | не выполнен Build Command |
| Бот оффлайн, ошибка токена | токен отозван или указан старый |
| Данные пропали после деплоя | нет Persistent Disk или не задан `DATA_DIR=/data` |
| Два бота отвечают | запущено два экземпляра |
| `/link` пишет, что проверка недоступна | не задан `STEAM_API_KEY` |
| Роли не выдаются | `ROLE_IDS_JSON`/имя роли не совпало, или у бота нет права Manage Roles |

## 9. ИИ-помощник (Gemini) и правила

### Что умеет

| Команда | Что делает |
|---|---|
| `/ping`, `!ping` | статус бота **и** ИИ: модель, число запросов и ошибок, состояние базы правил, ошибки за час |
| `/rules 2.2`, `!rules 2.2` | ответ по правилам. Номер пункта — мгновенно и точно, без ИИ; свободный вопрос — через ИИ |
| `/ask <вопрос>`, `!ask` | любой вопрос ИИ-помощнику |
| `/ai_status`, `!ai_status` | состояние ИИ, базы правил и последние ошибки (только модераторы) |
| `!ai_scan` | вручную обновить правила и разобрать ошибки (только модераторы) |
| `/health` | среди прочего — состояние ИИ, базы правил и хранилища GitHub |
| `/admlink <SteamID> <@участник>` | модераторская привязка за игрока: без проверки владения Steam, роли выдаются сразу |
| `/admunlink <@участник>` | модераторская отвязка |

Плюс фоновая задача каждые `AI_ERROR_INTERVAL_MINUTES` минут: если появились
новые ошибки, ИИ разбирает их и пишет в канал логов — что сломалось, почему
и что делать.

**Все логи ИИ** (запросы, ответы, ошибки, разборы ошибок, обновление правил)
уходят в канал `AI_LOG_CHANNEL_ID` (по умолчанию `1554796338661826660`).

### Настройка

1. Получи ключ: https://aistudio.google.com/apikey
2. Render → Environment → `GEMINI_API_KEY=<ключ>`
3. Проверь: `/ping` должен показать `🤖 ИИ: включён, модель gemini-3.8-flash`.

ИИ вызывается по Interactions API:
`POST https://generativelanguage.googleapis.com/v1beta/interactions`
с заголовком `x-goog-api-key`. Отдельный SDK не нужен — используется `aiohttp`,
который уже стоит.

### База правил — обязательный шаг

Страница `https://cs2red.ru/rules` — это SPA: сервер отдаёт только оболочку
сайта, текста правил в HTML нет (проверено). Поэтому бот берёт правила по
приоритету:

1. **`rules.txt` в папке данных** — самый надёжный способ. Скопируй
   `rules.example.txt` → `rules.txt`, вставь текст правил, положи в `/data`
   (на Render это постоянный диск) и выполни `!ai_scan`.
2. `RULES_API_URL` — если найдёшь настоящий JSON-эндпоинт правил
   (DevTools → Network на странице правил).
3. `RULES_URL` — страница правил.
4. Авто-поиск в JS-бандлах сайта (на случай, если текст зашит во фронтенд).

В канал логов ИИ придёт строка вида `📚 Правила обновлены: локальный файл
rules.txt: 42 пунктов` — по ней видно, какой источник сработал. Если ни один
не подошёл, бот честно скажет, что нужно положить `rules.txt`.

Кэш правил хранится в `rules_cache.json` рядом с данными и переживает
перезапуск. Обновление — раз в `RULES_TTL_HOURS` часов.

### Если ИИ не отвечает

| Симптом | Причина |
|---|---|
| `/ping` пишет «выключен (нет GEMINI_API_KEY)» | не задан ключ |
| В логах `HTTP 403` | ключ неверный или отозван |
| В логах `HTTP 429` | превышен лимит бесплатного тарифа, подожди |
| В логах `не разобрал JSON` | изменился формат API — пришли лог, поправлю |
| Правила «нет данных» | не положен `rules.txt` и не задан `RULES_API_URL` |
| `⚠️ ai_rules.py не загружен` | файл `ai_rules.py` не залит рядом со `script.py` |

Бот продолжает работать полностью и без ИИ: вопросы по правилам будут
отвечаться локальным поиском по тексту, а ошибки — уходить в обычный лог.
